Confirmed by repo-wide grep that this was the *only* live caller — no other code path was ever at risk. **Not fixed, flagged as a real follow-up**: the same Prisma model has several other stale fields (`iso_code`, `iso_numeric`, `thousands_separator`, `is_default`) that don't match the live table either — currently dormant (nothing reads them), a full model reconciliation (`prisma db pull` + review) is its own pass.
