| D29 | **D22 redesign → new package CLF (Cash Ledger Foundation).** Owner design discussion, all decisions owner-approved | 2026-09-25 | **Principles:** (1) accounting-period cutoff — every event is recorded when it happens with the facts at that moment; a closed session is never changed afterwards, corrections are new entries now. (2) A drawer session is only a custody **reconciliation window** over one drawer; it never affects finance outside its boundary. (3) **Every financial transaction is a voucher**; **custody events are operational, not financial**, and live in their own drawer transaction tables. (4) One physical event = one record. **Two domains:** *finance* (voucher lines: customer cash in/out, refunds, reversals, stored-value funding, over/short) and *custody* (session open/close, counts + optional denominations, drops, drawer↔drawer / drawer↔safe transfers, driver handover, close disposition, after-close deposit marking). Custody reads finance, never writes it; custody transactions only *move* cash between drawers (lines sum to zero per currency) — only finance creates or destroys cash. **GL:** one cash-on-hand account per branch+currency; drawers are operational detail below it. **Over/short:** the close emits an event; finance creates the voucher from it. **Expected cash** = finance cash voucher lines on the drawer + custody transaction lines on the drawer, in the window — computed from events, never from payment status. **Consequences:** mirror movements removed; `org_cash_drawer_movements_dtl`, `cash-drawer-cash-facts.ts`, `cash_drawer_mvt_id`, the three mirror wiring handlers and the planned `org_cash_sess_curr_dtl` retired. **No auto-recovery or continuous sessions** — cash arriving between sessions sits on the drawer ledger with no session and the next opening's expected amount includes it; `requires_session = false` drawers are reconciled by counts only. **Central gate** (one public API, domain-agnostic, pure policy) stamps drawer + session on every cash voucher line. **Drawer types** become `sys_cash_drawer_type_cd` with per-type rules (hard capabilities + overridable defaults). Drawer policy flags move into `org_fin_cash_ctrl_stng_cf` at DRAWER scope, managed from the drawer's own screen. The duplicate open path (D21) is merged. **Close:** opening/closing counts and denominations all **optional** (uncounted close is flagged); **disposition code mandatory**, notes mandatory only for `OTHER`/`PARTIAL_REMOVED`; after close: optional status + notes with actor/time and a change log, own permission. **Naming (owner):** all new drawer tables carry `_cash_drawer_`, session-only ones `_cash_drawer_ses_`, `trx` not "custody"; `org_cash_drawers_mst` and `org_cash_drawer_sessions_mst` keep their names. **No backfill of history semantics** (demo data only); old code and DB retired, not shimmed. **Planning refinements recorded in the plan (§4B.2, P1–P12), for owner review:** ledger sequence + drawer row lock replaces the shared/exclusive advisory-lock idea (a time-based close cut is unsafe); two-step close with a `CLOSING` status; reversals always mirror in the drawer ledger; cashier accountability starts from the opening count when entered. ## Cross-program note — Tenant Currency & FX (2026-09-25)

Migration **`0532_org_currency_cf.sql`** (written, not yet applied) touches this program's tables:

- Adds composite FK **`fk_ocd_tenant_currency`**: `org_cash_drawers_mst (tenant_org_id, currency_code)` → `org_currency_cf (tenant_org_id, currency_code)`. A drawer can only hold a currency the tenant has; the backfill creates an `org_currency_cf` row for every currency already on drawers, so existing data validates.

- Foreign cash = a drawer in that currency (CLF P12 unchanged); `org_currency_cf.allow_cash` is the tenant switch the drawer service will check.
