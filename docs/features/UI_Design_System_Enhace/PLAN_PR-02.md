# PR-02 Shared Components Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (owner's choice: inline, one review at the end). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One badge, a select that positions itself, a `src/ui` layer that never imports feature code, no duplicate component sets, shared components with no raw palette or physical-direction classes, and lint rules that stop all of these coming back.

**Architecture:** Status colours become locked semantic tokens (bg, border, text per tone) registered in Tailwind, with a contrast test. `CmxStatusBadge` becomes the only badge; domain badges map their codes to a tone. `CmxSelectDropdown` keeps its exported API and runs on `@radix-ui/react-select`. The top bar takes slots; the dashboard layout fills them with feature components. A class codemod (reused by PR-05 on feature folders) moves `src/ui` to semantic and logical classes. ESLint then guards the result.

**Tech Stack:** Next.js 16, React 19, Tailwind v4 (`@theme` in CSS), Radix UI, next-intl, Jest (jsdom), Storybook 10.

**Spec:** `THEMING_ARCHITECTURE_DESIGN.md` (wins on conflict) and `PR-02-primitives-badges-eslint.md`, same folder.

## Global Constraints

- Tones are exactly `neutral | info | success | warning | danger | brand`. They are component prop values like `size="sm"`, not stored codes, so the UPPERCASE rule for database codes does not apply.
- Every tone's text on its background is at least 4.5:1, in light and dark.
- No feature code imports Radix directly; `@radix-ui/react-select` is used only in `src/ui/forms/cmx-select-dropdown.tsx`.
- Shared components keep working in Arabic: logical classes only, chevrons and menus mirror.
- No new English literals in `src/ui`; labels come from `common.*` keys (search before adding; add both `en` and `ar`).
- Pre-launch: no `@deprecated` transition. Every importer of a removed name moves in the same task.
- Tests live under `web-admin/__tests__/`.
- Each task ends with ESLint on the changed files, the task's tests, and the progress update. Typecheck and build run in Tasks 3, 4, 6 and 10 (the tasks that touch many files). Use `NODE_OPTIONS=--max-old-space-size=8192` for both.

## Review Focus

1. Callers that pass `className` colours to the new badge: the class merge must let theirs win, and nothing should end up with two backgrounds.
2. Select inside a dialog, inside a scrolling table, and near the bottom of the window: the list must show above the dialog and flip upward when there is no room.
3. Select with a value that is not among the options, and with zero options or `isLoading`: the trigger still shows something sensible and the empty/loading text shows in the list.
4. Arabic: select list alignment and check-mark side, top bar menu side, badge icon side.
5. Codemod output where a class was built conditionally (`isRTL ? 'ml-2' : 'mr-2'`): must become one logical class, not two conflicting ones.
