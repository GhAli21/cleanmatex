# Tenant Guard Restoration

**Priority:** Urgent · **Opened:** 2026-09-25 · **Owner:** GhAli21 · **Status:** see [STATUS.md](STATUS.md)

## Why this package exists

`lib/prisma-middleware.ts` claimed to add `tenant_org_id` to every `org_*` query automatically. It registered through `$use`, which Prisma 6 removed, and `lib/db/prisma.ts` silently skipped registration when `$use` was missing. **The guard never ran.** Prisma connects as the `postgres` superuser, so RLS does not apply to Prisma queries either. On the Prisma path, the explicit `tenant_org_id` written by each developer was the only tenant barrier, and nothing verified it. (Found during POS hardening CLF-0-1, D32.)

## What replaces it

A Prisma **client extension** (`$extends`) in `web-admin/lib/db/tenant-guard.ts` that **checks** and never **injects**. Adding a filter silently changes what a query means. Rejecting is safer.
